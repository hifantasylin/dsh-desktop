# 05 Core Assets：资产库基础、编号与总表

> 本文件由 05-asset-library.md 第四批瘦身拆分而来，保留原规则文本。按主路由命中时读取。

---

## 一、什么时候调用本模块

用户出现以下需求时，调用本模块：

1. “建立资产库 / 素材库 / 角色资产 / 场景资产 / 道具资产”
2. “帮我整理参考图 / 统一角色图 / 管理出图结果”
3. “这个项目后面要持续出图、分镜、做 AI 视频”
4. “把项目档案里的角色、场景、道具整理成资产表”
5. “帮我规划文件夹结构 / 命名规则 / 版本管理”
6. “这几张图怎么编号，怎么传给分镜或视频模型”
7. “我要留档，后续新对话继续用”

如果用户只是要写故事，先回到 `01-script-creation.md`。  
如果用户只是要诊断剧本，先回到 `02-script-doctor.md`。  
如果用户只是要改台词，先回到 `03-dialogue-expert.md`。  
如果用户已经有定稿剧本并要转 AI 视频分镜，先确认是否已有资产库；没有则建议先建立本模块。

资产库完成后必须交接给 04/06：保留已有平台节奏档案和节奏档位，不在 05 内重判剧情节奏；列出当前段真正需要的角色、场景、道具、首帧、调度和 SCV 图，提醒单组 06 可投喂图片参考最多 9 张，超出时给筛选、合并、转文字或拆组建议。

## 二、资产库的核心目标

资产库要解决 5 个问题：

1. **一致性**：同一个角色、场景、道具在不同场次、不同模型、不同生成批次中不漂移。
2. **可追溯**：每张图、每条 prompt、每个版本都知道来源、用途、状态。
3. **可交接**：剧本、台词、分镜、AI 视频 prompt 都使用同一套资产编号。
4. **可扩展**：后续新增角色、场景、道具、服装、镜头参考时，不破坏旧编号。
5. **可复盘**：知道哪些资产已定稿、哪些只是参考、哪些被废弃。

## 三、资产目录与命名规范（dsh 落盘单源）

目录根固定为工作空间 `.assets/<项目名>/`；`media_asset_save` 落盘位置为 `.assets/<项目名>/<dir>/<name>`，**`dir` 必填**（由 LLM 按本节模板传参），`category` 只作 assets-index 类别标签（枚举固定）。分工：**目录树、编号、版本、状态以本节为单源**；工具参数、废弃纪律与 assets-index 机制见 `references/deepseek-harness.md` §2 / §3.2 / §3.3。

**与 chaoge 原结构的差异（刻意取舍）**：`00_项目档案`（文本走 §3.1 根目录 `.md`）、`06_分镜交接`（映射表在资产总表）、`07_AI生成记录`（prompts/ 已承担）、`08_人群调度`（CR 文字卡在资产总表）不启用，避免双轨；`99_废弃` 统一为目录 + `_废弃_<时间戳>` 命名（见 deepseek-harness.md §3.2）；`10_导演工作图`/`11_视频成片`/`12_BGM`/`13_封面` 为本结构扩展（chaoge 体验版无分镜/视频/封面）。

**多集项目**：系列级资产（`<项目名>_资产库.md`、`01_角色/`、`02_场景/`、`03_道具/`）跨集共享；集级文本资产（`EPxx/EPxx_剧本.md`、`EPxx/EPxx_分镜.md`、`EPxx/prompts/`）与集级媒体（`11_视频成片/EPxx/`、`12_BGM/EPxx_…`）一律带 EP 前缀，**绝不在系列根重建集级文件名**（会覆盖前一集）。

### 文件名与版本、状态

- 文件名默认 `编号_名称_用途`（如 `CH001_花十_本体`），**版本与状态记录在资产总表，不写进文件名**——重做失败移入 `99_废弃/` 并改名 `_废弃_<时间戳>`（`references/deepseek-harness.md` §3.2），新版本用原名落盘。
- 需要显式留档多版时（如 v2.0 大改）才加后缀：`编号_名称_v主.子_状态`（如 `CH001_花十_本体_v2.0_定稿.png`）。
- 版本含义沿用第四节：v0.x 探索 / v1.0 首定稿 / v1.x 小改 / v2.0 大改。

### 目录使用原则

- 资产总表（`<项目名>_资产库.md`）是核心索引；没有进入总表的图片不算正式资产。
- 参考图落 `01_参考图/`，定稿落 `02_定稿图/`；状态同时在资产总表登记（参考 / 定稿 / 废弃）。
- 废弃资产不删除：移入 `99_废弃/` 并改名 `<原名>_废弃_<时间戳>`（`references/deepseek-harness.md` §3.2），记录原因，避免重复踩坑。

所有资产必须有稳定编号。编号一旦确认，不因角色改名、场景改名而改变。

### 版本号规则

```text
资产编号_名称_v主版本.子版本_状态
```

示例：

```text
CH001_花十_v1.0_定稿
CH001_花十_v1.1_改发型
SC001_茶餐厅_v0.3_参考
PR001_银色打火机_v2.0_定稿
```

版本解释：

- `v0.x`：探索阶段，不稳定。
- `v1.0`：第一版定稿，可进入分镜和视频生成。
- `v1.x`：小改，不改变资产核心身份。
- `v2.0`：大改，外观、时代、身份识别明显变化。

## 五、资产状态规则

每个资产必须标注状态。

| 状态 | 含义 | 能否交给分镜/视频 |
|---|---|---|
| 待补 | 只有名字或描述，未生成图 | 不建议 |
| 参考 | 可启发，但未确认 | 可作为参考，不可作为唯一依据 |
| 候选 | 有 2-5 个可选方向 | 不建议，需用户定稿 |
| 定稿 | 用户确认，进入资产总表 | 可以 |
| 需重做 | 方向错误或不稳定 | 不可以 |
| 废弃 | 明确淘汰 | 不可以 |

输出任何资产表时，必须明确状态，不能只列名字。
