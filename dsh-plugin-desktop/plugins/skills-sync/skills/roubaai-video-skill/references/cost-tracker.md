# 成本记录（cost-tracker）

**文档**：`.assets/<项目名>/cost-tracker.md`（与 `media-cost.jsonl` 同目录，一项目一账）
**职责**：只做三件事——价格基准（估算）/ 预期管理 / 预期外开销管理。
**实际成本**：由 media 插件自动记账（`media-cost.jsonl`，每次生成完成自动写一行）；本文档**不手记原始数据**，只在用户问成本/结算时调 `media_cost_summary` 拉实际，做对比和分析。
**价格基准单源**：实际单价以 `references/deepseek-harness.md` §2 各工具说明为准；下表仅为估算基线。

---

## 用户问成本时怎么执行

**触发**：用户说「花了多少 / 这个项目成本 / 哪个镜头最贵 / 超预算了吗 / 成本怎么算」等成本相关话。

**执行（按顺序）**：
1. 调 `media_cost_summary`（`project=<项目名>`）——拉实际成本账（每 label 首次/重试次数/累计，按类型小计）。
2. 读本文档 §2 —— 拿预期成本（若还没建预期，跳到第 5 步并标注「预期未建立」）。
3. 按 §3 做「预期 vs 实际」对比：逐项差异 + 原因分析（重试/分辨率升级/临场追加/模型变更/估算偏差）。
4. 把对比结果**追加写入本文档 §3**（记录拉取时间）+ 更新 §4 主要开销排行；重试原因从 §5 读。
5. 回复用户。

**给用户的回复应包含**：总计（USD + CNY）/ 与预期比（超或省、差多少）/ 主要开销 Top / 超预期原因 / 建议（如降分辨率、减少重试）。

**注意**：`media-cost.jsonl` 是系统自动写的**只读账本**，查询/汇总不修改它；重试「为什么」在 §5（账上只有次数）；用户没问成本时**不主动汇总**，避免打扰流程。

## 3. 预期外开销管理（核心：实际 vs 预期 + 原因分析）

**数据来源**：系统自动记账 `media-cost.jsonl`；**用户问成本或结算时**调 `media_cost_summary` 拉实际（含每 label 首次/重试次数/累计），按下面格式追加对比，并**记录拉取时间**。

```
## 预期 vs 实际（拉取于 2026-XX-XX XX:00）
| 项目 | 预期(USD) | 实际(USD) | 差异 | 原因分析 |
|------|----------|----------|------|---------|
| 图片·角色 | $0.04 | $0.06 | +$0.02 | 角色临场加了一套服装（2 张） |
| 图片·场景 | $0.05 | $0.05 | 0 | |
| 视频·镜01 | $0.25 | $0.25 | 0 | |
| 视频·镜02 | $0.25 | $0.76 | +$0.51 | 重试 3 次：2 次动作偏差 + 1 次内容违规 |
| **总计** | $X.XX | $X.XX | +$X.XX | |
```

**差异为正（超预期）时必须写明原因**，常见分类：
- **重试**：同镜生成多次（账上自动标 retry，次数 `media_cost_summary` 可见）——为什么重试见 §5
- **分辨率/规格升级**：480p→720p、1K→2K、加 `generateAudio`
- **临场追加**：角色/场景/镜头临时增加，不在原计划
- **模型变更**：换更贵的模型
- **估算偏差**：单价档估错（如实写，下次校准）

## 5. 重试记录（次数系统自动数，原因 LLM 补写）

账上自动标 retry（同一 project+label 第 2 次起）；**「为什么」账不知道，LLM 补写**。每次重试前想清楚原因，追加一行，不覆盖：

```
| 时间 | 镜号 | 第几次 | 失败/重做原因 | 处理方式 |
|------|------|--------|--------------|---------|
| 2026-XX-XX 11:00 | EP01_镜02 | 2 | 提示词问题：动作描述与分镜不符 | 改写衔接句后重试 |
| 2026-XX-XX 11:05 | EP01_镜02 | 3 | 内容违规（violation） | 调整措辞后重试 |
| 2026-XX-XX 11:10 | EP01_镜02 | 4 | 下载失败（网络） | 只重试拉取，未重新生成 |
```

原因分类：提示词问题 / 参考图问题 / 内容违规 / 网络·下载失败 / 模型·服务端 / 用户要求重做。网络/下载失败只重试拉取不重新生成。
