# 视频制作skill（roubaai-video-skill · v4.0）

这是一个总控型 skill。先判断用户当前处在哪个阶段，再只读取必要的 reference。不要一次性读取所有 reference，除非用户明确要求完整流水线。

跨多阶段任务（3 个以上阶段，或用户要「从 0 到 1 开发完整项目 / 全流水线」）默认走**团队化工作模式**：主 agent 变为 captain，拉专职 member 团队推进，不自己串行写全部模块。详见「团队化工作模式」章节。

默认使用中文输出，除非用户明确要求英文或其他语言。

## 总控原则

1. **只读必要模块**：本文件只负责路由、导航和全局红线。各专科详细规则以对应 reference 为准。
2. **先补最早缺失环节**：用户跨越多个阶段时，先判断最早缺失的环节，例如缺资产和分镜却要 Seedance prompt，先提示 `05 -> 04 -> 06`。
3. **输出必须可继续推进**：每个阶段结束时告诉用户下一步、所需材料和可直接复制的调用语。
4. **短视频平台要有节奏档案**：如果作品用于抖音、快手、小红书、视频号、B 站短视频、红果、竖屏短剧，或用户说“留人 / 完播 / 爆款 / 别太慢”，必须建立或暂定平台节奏档案。
5. **慢镜头必须有功能**：慢镜头、沉默、空镜和留白可以保留，但必须承担情绪、悬念、信息、人物关系、视觉记忆或下一段蓄力功能。
6. **信息不足时不空转**：不影响推进时合理暂定并标注；会导致下游严重错误时再追问。
7. **自动节奏判档贯穿全链路**：从项目档案、剧本写作、剧本会诊到 04 分镜和 06 成品提示词，必须识别或继承节奏档位。默认由 AI 按剧情自动判定每组使用 `电影感中速 / 短视频中高密度 / 高密度动作或强钩子 / 慢节奏但高信息`，用户明确指定时覆盖自动判断。04 必须把每个大分镜的节奏档位交给 06；06 必须继承执行，不得只保留泛化“平台节奏”四个字。
8. **模块交接不可丢**：每个子模块结束时至少交代当前阶段、当前节奏档位（如已有）、已确认内容、主要风险、下一步建议、建议调用模块、下一步需要材料和可直接复制调用语；05/04/06/07 还要额外交代资产映射、图片预算、段末状态或声音后期状态。

## 团队化工作模式

**何时启用**：需求跨越 3 个以上阶段，或用户明确要「从 0 到 1 开发完整项目 / 全流水线 / 完整开发」。
**何时不用**：单阶段任务（如只做台词诊断、只转一次分镜）→ 主 agent 直接按下方模块路由做，**不建队**；用户明确要求「你自己做 / 不要多 agent」时也不建队。

启用后主 agent 变为 **captain**，按以下流程编排：

1. **阶段判定**：先读 `.assets/<项目名>/` 判断项目进行到哪一步，从**最早缺失环节**开始，不重复已完成工作。
2. **建队**：`agent_teams_create` → 读 `references/00-team-personas.md` 取 persona 全文 → `agent_teams_add_member` 按需拉 member（**只拉本轮需要的，不必全拉 7 个**）。
3. **派工**：`agent_teams_create_task` 按该文件 §2 的 DAG 建 task，带 `dependencies`；派工时写明本次 task 需读的具体 reference。
4. **门禁**：按该文件 §3 在触发点插入审核 task；**任一门禁未过，下游 task 不得开始**。提示词门禁最严（提示词一错，后面生成全废）。
5. **监控**：`agent_teams_status` 轮询；halted 先读原因——歧义用 `agent_teams_ask_user`，缺依赖就补 task。
6. **收尾**：汇总各 member 产物路径 + 审核结论汇报用户 → `agent_teams_delete` 归档。

**产物交接**：所有 member 产物落盘 `.assets/<项目名>/` 对应子目录，下游从磁盘读取，不靠消息正文传大内容。素材名必须与 `./assets` 文件精确一致；节奏档位、角色表演指纹、`@图N` 用途必须一路继承到提示词与剪辑。

**关键节点等用户确认**：不擅自跨过用户确认点。

## 05/04/06 图像视频链路红线

进入图片或视频生产链路时，要把“默认基础格式”和“按需增强”分开处理。普通段落保持轻量、顺手、可直接投喂；高风险才启用增强。

### 05 资产库

读取 `references/05-asset-library.md`。必须按该文件规则处理：

- 角色、场景、道具、服装、妆发、风格、参考图、生成图、视频参考和 `@图N` 映射。
- `ST` 视觉风格锁、`CL` 色彩光影设计、`NP` 防跑偏负面词包。
- 核心角色默认四视图；核心/高级角色可额外 3:2 高级设定资料卡。
- 核心场景/高穿帮场景按需 `SCV` 多角度空间包。
- 公共空间按需 `CR` 人群/群演调度卡。
- 强连续段按需场景母版、空间解析、MAP 调度图、点位表。
- A/B 首帧风险段按需 `FF` 首帧需求卡、首帧图 prompt、参考图用途映射。
- 同一关键道具已在 SC/SCV/FF 中可见且还要上传 PR 外观图时，必须建立 `PR` 道具单实例锁。
- 资产库交接必须保留已有节奏档位、角色语言/表演指纹、`@图N` 用途和单组 06 图片预算；每个 Seedance 单元最终图片参考最多 9 张，超出时先筛选、合并、转文字或拆到下一组。
- 角色定稿图生成命中"AI 感重/油腻/要真人实感"或项目为真人实景档时，补读 `references/05-anti-ai-realism.md`（材质重量、信息量克制、光源有实体来源、不完美=真实感、词级禁令并入本次 NP）；风格化档只用反完美通用部分，不引入实拍基底。

### 04 AI 视频分镜

读取 `references/04-ai-video-storyboard.md`。必须按该文件规则处理：

- 04 不修剧情和台词，只把定稿剧本转成可生成视频的大分镜、镜头语言和 prompt。
- 每镜保留焦段、光圈、景深与焦点锁、机位、构图、运镜、主体动作/表情、台词与语气、光影、限制、下一段衔接。
- 下游为 Seedance/豆包/火山方舟时，多段输出要判断相邻段边界：视频延长 / 首帧图 + 调度图 / 只首帧图 / 只调度图 / 普通衔接。
- 强连续、回切、高穿帮、多人站位、窗内外/柜台内外/车内外等场景按需建议 `SCV/FF/MAP/SB`。
- 公共空间判断人群/路人调度；无人群需求时禁止额外人物。
- 打斗、追逐、动作戏、特殊转场或用户要求强化运镜时，再读 `04b-camera-action-cheatsheet.md` 路由；普通追逐/转场/情绪运镜只用 04b 本体，具体动作戏再按类型只读命中的子库：自由格斗读 `04b-free-combat.md`，武侠/冷兵器读 `04b-wuxia-weapons.md`，超能力/异能读 `04b-superpower-action.md`，战场/群战读 `04b-battlefield-action.md`。不要默认读取全部动作子库。
- 04b 动作子库命中后必须把动作密度、接触点/受力结果/战线变化和节奏档位建议回填给 04；动作段默认优先考虑 `高密度动作或强钩子`，除非剧情功能明确需要降档。
- 分镜是回忆片段 / 主观视角 / 沉浸叙事（观众=角色眼睛）时，补读 `04b-pov-first-person.md`（POV 视野化写作：不写"我"、写画面入画/出画/变近变远、声音轨标远近）；POV 规则不改 04 字段，只改镜头轨/声音轨的写作语言，随 04 一并交给 06。
- 每个大分镜前置单元必须自动输出 `节奏档位判定`、理由、建议镜头密度和交给 06 的节奏继承说明；用户不满意时允许指定某一组改档，不重做全项目。

### 06 视频生成（Harness 原生）

读取 `references/06-seedance2-adapter.md`；**先按 §0 模型判定**——config `model` 含 `seedance-2.5` 或用户明确"用 2.5 / 30s 大分镜"时改读 `references/06-seedance25-adapter.md`（4-30s，全局设定 + 时间戳分镜剧本）；否则 2.0 现状（4-15s / C-A-B）保持不变。06 的详细格式、红线、自检和示例以对应文件为准。总控只保留这些不可丢规则：

- 先推荐并允许选择 `A 标准字段化详细版 / B 导演执行增强版 / C 导演轨纯净版`；用户不指定时默认用 `C 导演轨纯净版` 继续。
- 模板调度必须清楚告诉用户：`C 导演轨纯净版` 是默认，适合绝大多数 06 成品提示词，镜头数不设限、需要直接投喂且控制 1900 字以内的段落；`A 标准字段化详细版` 只在用户明确要求完整字段、1-3 个镜头高精度控制、审查镜头漏项或教学拆解时使用；`B 导演执行增强版` 只在一镜到底、复杂运镜、动作戏、强遮挡转场、多人调度或强声音叙事时使用。
- 默认恢复旧版手感但不默认展开旧版 11 字段：C 模板使用 `特别注意 / 素材锚定 / 参考-连续性声明（按需） / 风格锁定（按需） / 场景锚定 / 镜头轨 / 声音轨 / 硬锁 / 段末状态`，把旧版的焦段、光圈、景深、机位、构图、运镜、动作、台词、光影、限制、衔接合并进镜头轨，不得丢失关键控制。
- `特别注意` 只放本段最高优先级的画面、摄影、表演红线，例如全程手持、人物静止、不要继承参考图构图、严格按镜头轨重新构图；不要在这里重复声音要求。
- `参考/连续性声明` 只在命中时输出：参考图只取人物关系或环境不继承构图、承接上一段动作但不用尾帧首帧、使用视频参考但不延长、启用首帧/调度/道具单实例锁时，都在这一行写清“只参考什么 / 不参考什么”。
- `风格锁定` 只在用户或资产给出 CG、UE5、MetaHuman、动捕、3A 游戏过场、禁止真人质感、实时渲染等风格要求时输出；普通真人写实段不强行输出。
- `镜头轨` 默认格式为 `N｜镜头功能标签｜镜头/焦点｜动作/台词｜光影/转接`。镜头功能标签必须根据当前剧情和本镜信息增量自动提炼，例如“误导开场 / 证据露出 / 情绪反咬 / 道具异变”，不得固定套用“开场钩子 / 动作打断 / 危险规则 / 旧伤暴露 / 关系反转 / 段末异变”。
- `通用后缀` 默认只保留高收益项：`音效说明 / 道具约束 / 文字约束 / 光线约束 / 风格约束`，`段末状态` 单独保留；`一致性约束 / 节奏约束 / 画面规格` 默认不输出，其信息并入人物锚定、具体镜头限制、投喂信息和段末状态，只有用户明确要求时才追加。
- 总时长、画幅、模式、任务类型和参数建议默认放在代码框外；纯净提示词代码框默认从 `素材：` 开始。
- 纯净提示词中的 `全局控制` 只允许写场景、情绪、光影、风格、动作密度和镜头执行原则；不得写 `9:16 / 13-15秒 / 1080p / 参考生视频 / 多模态参考` 等平台参数。参数只放代码框外投喂信息。
- 正文优先按 C 的 `镜头轨` 或 A 的 `分镜字段` 推进，不默认写硬时间戳；默认保持 04 的镜头顺序、数量和节奏意图，不为压字数随意拆镜头或合并镜头。
- 06 必须继承 04 的 `节奏档位判定`。如果 04 未给出，06 先按平台、剧情功能、对白长度、动作密度和本段所在位置自动补判；节奏档位和理由放代码框外，纯净提示词只写成可生成的镜头节奏、动作密度和慢词控制。
- 纯净提示词的衔接必须写成模型可生成的可见画面状态或动作转接，不写 `接下一大分镜 / 接下一段 / 承接下一段 / 接分镜2` 这类只给人看的管理语。最后一镜只写段末可见状态。
- 06 不改写台词，只做台词可执行性检查：保留原台词，估算对白字数、自然语速、停顿和表演补偿；若建议时长内无法以自然语速说完，优先延长到 15 秒内、按台词节拍拆连续单元，或建议回 `03` 精修，不得强行提速或擅自删改台词。
- **唯一闸门是 1900 字，镜头数不设限**：一个单元写 4 个、5 个分镜都可以，按规范写完不超 1900 字就不必拆。`2000` 是本技能自律的出门闸门（**非平台限制**：Seedance 2.0 约 5000 字符，2.5 控制台 15000 字、API 侧无硬性上限）。输出前必须估算代码框内纯净提示词字数；超过 1900 时先删低收益后缀、管理话术和重复字段（**不删画面细节**），仍超限才按分镜边界拆成连续单元（每单元约 3 个分镜），用上一单元 `段末状态` 承接下一单元第一帧，不在单个镜头内部硬拆。
- 高级增强只在命中时启用：视频延长、FF 首帧、SCV 角度、MAP/SB 调度、CR 人群、PR 道具锁、复杂运镜、声音叙事。
- 普通段落默认用角色名 + `@图片` 参考；需要人物锚定时固定写 `将 @图片N 中的[身份/外观/服装]定义为 <角色名>`，后续镜头用 `<角色名>` 指代；没有正式名字时临时命名为 `<角色A>`、`<角色B>`，不使用编号主体标签做人物锚定。
- 代码框内只写当前生成事实、素材用途、画面动作、声音、保持项和具体可见禁止项；不要写“未启用 / 无则删除 / 不使用 / 不继承 / 不替代”等管理话术。06 只允许环境声、对白原声和同步音效，默认不生成 BGM；BGM 留给 07 后期声音设计。声音轨可写多声源、画外音、非人声和同时出声的音量层级。
- 输出前必须做素材编号一致性自检：镜头轨里出现的 @图片/@视频/@音频 编号必须已经在素材锚定或参考/连续性声明中定义，且道具、角色、场景编号不能混用。
- 每一组可投喂提示词 / 每个 Seedance 单元实际使用的图片参考总数最多 `9` 张，包含人物、场景、道具、首帧、调度图、位置参考图、SCV 角度图等所有图片；项目资产库本身可以超过 9 张，但单组输出必须筛选、合并或转文字，不得在同一组提示词中引用超过 9 个 `@图片N`。

## 07 后期音乐与声音

读取 `references/07-post-music-sound-design.md`。07 不替代 06 的单段视频音频提示词；它负责成片或粗剪后的整体声音策略、BGM 情绪曲线、Cue Sheet、音乐搜索词、AI 音乐生成提示词、音效和版权检查。

- 07 必须继承 04/06 的节奏档位、台词自然语速风险、段末状态和声音轨现状，用于安排 BGM 进出点；不得把 BGM 写回 06 纯净视频提示词。
- 用户明确要求实生成 BGM 时，按 `references/07-music-prompt.md` 做决策并写 `generate_music` 的 `description`/`lyrics`（模式映射、与剧情对齐、描述公式与词表）。

进入 07 前优先收集：成片/粗剪总时长、每段顺序和时长、对白/字幕/旁白、04/06 交接信息、情绪爆点/反转点/沉默点/结尾钩子、找音乐方式、商用需求、目标平台和画幅。

## 平台节奏档案

如果触发短视频平台节奏管理，至少记录：

- 发布平台、画幅倾向、作品类型、目标时长、目标受众。
- 节奏档位/密度：电影感中速 / 短视频中高密度 / 高密度动作或强钩子 / 慢节奏但高信息。默认由 AI 自动判定，用户可覆盖。

- 本段钩子、信息增量、情绪推进、呼吸镜头功能、段末继续看的理由。

没有用户明确提供时，根据作品类型暂定并标注【暂定】。

## 项目状态保持

同一项目的全部文本与媒体资产持续保存在 `.assets/<项目名>/` 下（文本落盘映射见 `references/deepseek-harness.md` §3.1；媒体资产目录树/编号/命名/状态单源见 `references/05-core-assets.md` 第三节），跨对话/跨阶段从磁盘续接。

如果新输入和已保存状态冲突，先指出冲突。只有冲突会影响后续创作、资产、分镜、视频生成或后期声音设计时，才要求用户决策。

## 工作方法

1. 判断当前任务属于哪个模块。
2. 只读取必要 reference。
3. 遵守被读取 reference 的自检、流程、输出格式和红线。
4. 需要多个模块时，完成一个模块后先交接，再进入下一个模块。
5. 用户给出明确任务时视为已确认，可以直接执行；只有缺少会影响结果的关键信息时才追问。
6. 如果 reference 要求开场自检，只做内部自检，不默认向用户输出完整自检报告。
7. 最终回复发出前，检查正文、表格、代码块、提示词、剧本正文、分镜字段、视频生成提示词和音乐 prompt 是否完整结束。
